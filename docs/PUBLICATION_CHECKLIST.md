# Publication Checklist

The repository is intended to become public, but this package does not create it or authorize a push. The owner must approve the final destination, license and sanitized artifact set.

## Content and identity

- Use Agent Proof Lab or the owner's chosen neutral name.
- No employer branding, customer identifiers, internal project names, proprietary code or production screenshots.
- Use fictional organizations and synthetic users throughout.
- Keep third-party product names factual; do not imply sponsorship or endorsement.
- Include known limitations and exact tested versions.

## Licenses and dependencies

- Confirm the code license and copyright owner before adding the final LICENSE.
- Inventory direct and transitive licenses, image provenance and redistributed assets.
- Do not copy vendor logos, proprietary client code or container images into the repository.
- Document externally hosted services and any account, authorization or licensing requirements.

## Evidence and security

- Run all required local tests from a fresh clone.
- Bind reports and recordings to the candidate revision.
- Publish failed and blocked cases honestly; do not cherry-pick a success-only sample.
- Scan source, history and artifacts for credentials and private material.
- Review screenshots/video manually; text scanning alone is insufficient.
- Do not publish raw provider payloads merely because a script removed a token field.
- Record cleanup and remaining local resources.
- Confirm five real application screenshots, three animated GIFs and three static posters exist, decode and match `docs/assets/media-manifest.json`.
- Verify every README media embed, alt text, caption and fallback path from a fresh clone; review desktop and narrow rendered layouts.
- Keep local-render verification distinct from actual GitHub-render verification. Record the latter as NOT_RUN until the approved repository/ref exists; do not publish merely to pass a check.

## Article

- Separate DOCUMENTED, DESIGNED, EXECUTED and UNKNOWN claims.
- Do not convert test expectations into test results.
- Link actual public artifacts only after they exist.
- No general speed, cost, security or vendor-ranking claims from a handful of demos.
- No fabricated first-person retrospective.

## Approval

Owner review is required for public repository creation, push, provider-app installation, external post and recording upload. The build agent should return a local prepared candidate and exact proposed actions.
