# Learnings: expected vs observed

Each entry records what we expected *before* running something, what we actually observed, why, and what changed as a result. The expectations in the second table were committed before the W5 verification runs so they cannot be rewritten with hindsight. Observed values reference run IDs in `artifacts/` or the spike output.

## Patterns

The same few lessons kept recurring. Each one names the rows that show it.

- **A passing test that can't fail tells you nothing.** F5-A1 passed while every adapter failed to load (L-020). An invalid mutant would have counted as "not uncaught" (mutation row). Before trusting a green test, make it fail on purpose once.
- **Missing evidence is not zero.** The easy default for "I could not look" is `0` or `false`, and it reads exactly like "I looked and found nothing" (L-021, L-017). Keep the key absent with a reason and let the report say UNKNOWN.
- **The reader must not share the writer's credentials.** The collector got its own Slack token, Floci key and read-only ledger handle. Even so, the emulator's simulator accepted the worker's token (L-019), so the real boundary is which process knows which URL. The Floci key separation is still unverified.
- **Documented is not seedable, and seedable is not enforced.** Docs said event callbacks go to "configured webhook URLs" but the public seed path dropped them (L-001). Docs said the simulator needs an authenticated token, and any token passed (L-019). Read the docs for intent, then test the behavior you depend on.
- **Regenerating can launder.** A tool that rewrites its own integrity record on every run will bless tampering (L-022). Verify before you regenerate.
- **The composition is its own test subject.** Two fixes that each passed their branch's gates broke F1-A2 and S2 once merged (L-025, L-026). Only the full harness on the merged tree caught it. Run the whole suite after every merge, not just the new tests.
- **Identity has to cover what it claims to cover.** `dirty: true` with a `patch_sha256` that ignores untracked files describes neither the tree nor the change (L-024). Run evidence from a clean tree.
- **Expectations should name their unit.** "collect-case overhead under 30%" was met or missed by a factor of 180, depending on what overhead meant. Write the measurement into the expectation before running it.
